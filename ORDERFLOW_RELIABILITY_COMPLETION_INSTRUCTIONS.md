# OrderFlow reliability completion overlay — use this first

This is a **repository overlay**, not a replacement checkout. Extract at the root of your existing `orderflow` Git repository. It includes code and tests for the outstanding application-level requirements, the migration, benchmark command, and updated documentation. It deliberately omits the generated Word/PDF draft so those do not accidentally become submission evidence before the report is finalized.

## 1. Extract

```bash
unzip -o ~/Downloads/ORDERFLOW_CAPSTONE_RELIABILITY_COMPLETION.zip -d .
```

The exact Postman collection path is `docs/postman/OrderFlow.postman_collection.json`. Check it with `ls -lb docs/postman`; no rename is needed if that exact name is present.

## 2. Keep draft reports out of Git

An earlier staging command may already have staged the local report drafts. Unstage those files before staging the completed code:

```bash
git restore --staged submission/OrderFlow_Applied_Software_Project_Report_DRAFT.docx submission/OrderFlow_Applied_Software_Project_Report_DRAFT.pdf 2>/dev/null || true
```

The bundle's `.gitignore` excludes `submission/*_DRAFT.*`. Do not stage `.env`, passwords, JWTs, webhook secrets, SQL backups, or real user/payment data.

## 3. Apply the reliability migration and run tests

Keep `ORDERFLOW_TEST_DATABASE_URL` set to the **dedicated** `orderflow_test` database in the same terminal. Follow `INTEGRATION_TESTING_MILESTONE.md` if it needs to be set again; do not print or paste the URL.

```bash
chmod +x scripts/*.sh
./scripts/verify-residual-milestone.sh
```

The verifier starts PostgreSQL/Redis, applies migration `000007` only when missing from the two exact local database names `orderflow` and `orderflow_test`, runs `go mod tidy`, formats Go files, runs `go test -count=1 ./...`, the race-enabled integration suite, `go vet`, and `git diff --check`. It refuses if the existing schema is missing prerequisites or the databases cannot be identified. It does **not** drop/recreate a database.

Next, build and start the image and check the real API health endpoints:

```bash
./scripts/docker-smoke-test.sh
```

Then collect actual API-level before/after measurements:

```bash
./scripts/benchmark-api-cache.sh
```

This launches two local containers against the same PostgreSQL data (Redis disabled versus enabled), warms each endpoint, measures `GET /products?page=1&limit=20` under the configured concurrency, reports p50/p95/mean and throughput, and saves the measured output under `docs/evidence/performance/`. Defaults are 300 requests and 10 concurrent workers; override `ORDERFLOW_BENCH_REQUESTS` and `ORDERFLOW_BENCH_CONCURRENCY` to repeat a workload. For an additional repository-layer microbenchmark, run `./scripts/benchmark-product-cache.sh`. Do not assume Redis wins or insert invented results.

## 4. Stage, inspect, commit, and push

Only continue if every command above passes. Then:

```bash
git status --short
git add -A
git diff --cached --check
git diff --cached --stat
git status --short
```

Inspect the staged list: there must be no `.env`, credentials, database dumps, or `submission/*_DRAFT.*` files. If anything unintended is staged, unstage it before committing. Then:

```bash
git commit -m "feat: harden order lifecycle and reliability"
git push origin main
git log -1 --oneline
git status --short
```

Open GitHub Actions and confirm the run corresponds to the new HEAD SHA and passes. The prior green CI run at `60c255b` cannot validate this new overlay.

## What this overlay adds

- Multi-product orders with server-calculated totals, item-price snapshots and atomic reservations.
- HTTP order idempotency: same user/key/payload returns the original order result; different payload with the same key returns `409`.
- Payment callback amount/currency checks and a stored failure reason.
- Successful-payment stock consumption plus `ORDER_FULFILLED` movement in the same transaction; callback replay does not consume stock twice.
- Safe expiry of old unpaid orders and reservation release; the expiry worker excludes orders with pending/successful payments and rechecks after locking to reduce payment/expiry races.
- Admin order, sales/payment, and inventory/low-stock reports.
- Redis product-read TTL caching and mutation invalidation, plus a PostgreSQL-versus-Redis benchmark.
- Migration `000007`, integration tests, CI walkthrough, updated OpenAPI, Postman, HLD/LLD and report source.

## Still not completed by code alone

- **Performance results** must be generated by the benchmark on your Mac and recorded truthfully.
- **AWS deployment** requires account/region/network choices and explicit billable-resource approval; this overlay contains documentation, not live infrastructure.
- **Real payment-provider recovery** is not claimed: payment callbacks still use the project's mock provider, and scheduled reconciliation reports issues read-only because no external provider lookup contract is configured.
- **Screenshots and final Word/PDF/submission ZIP** are deliberately held until the code and CI are final, per the agreed plan.
- **CI walkthrough**, previous Lambda submission review, and post-submission Go-architecture walkthrough remain learning/review items. The old Lambda source/repository is not part of this overlay.
